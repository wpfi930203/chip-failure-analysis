# 芯片失效闭环管理（chip-fa-closed-loop）

## R · 原文锚点（≤150 字/段）

**R-1 整体观念原则**（《失效分析——基础与应用（第2版）》第3章）：
> 「一旦失效就要把设备—环境—人（管理）当作一个整体（系统）……如果孤立地对待失效部件，或局限于某一个小环境，往往使问题得不到解决。」

**R-2 四M 分析法**（同书第3章）：
> 「所谓"四M"分析方法，是指将 Man（人）、Machine（机器设备）和 Media（环境介质）和 Management（管理）作为一个统一的系统进行分析的方法。对于一个比较复杂的系统常采用此种方法。」

**R-3 从现象到本质**（同书第3章）：
> 「从现象分析问题导入，进而找到产生现象的原因，即失效的本质问题」——看到断口/烧毁形貌不等于结案，必须回答"为什么会出现这个现象"。

**R-4 结果验证闭环**（《电子元器件失效分析与典型案例》第2章）：
> 「失效分析的结果是否正确，只有在实际应用中才能得到验证。……使失效分析、应用验证构成闭环系统，这一点对于三方都是有益的。」

**R-5 失效环境调查清单**（同书第2章 2.1）：
> 「1.批次认可……2.发现失效的地点和时间……3.产品记录……4.工作条件……5.失效详情：失效类型（特性退化、完全失效或间歇性失效），失效比例和批次情况等。」

## I · 骨架（内化的判断逻辑）

1. **失效信息完整性先于技术分析**——五要素清单（批次/时空/产品记录/工作条件/失效详情）任一缺失，都可能把内因误判为外因或反之。失效详情中的**失效比例与批次聚集性**决定走单件归因还是批次归因。
2. **整体观念 → 系统边界**——器件失效放进"设备—环境—人（管理）"三元系统里审；孤立看器件是失效分析最常见的失败模式（书中继电器案例：仓库氨介质来自门外鸡粪堆，不扩大环境边界永远查不出）。
3. **四M 逐因素撒网 → 再收口**——先宽后窄：人/机/介质/管理四路分别列假设，用排除法逐个审查；复杂系统不易丢失因素，但要"有所侧重"，避免平均用力。
4. **归因要过统计关**——多因素候选时，凭工程直觉排序不可靠；多重秩检验式的显著性比较可避免"选了看起来合理的、排除掉真正主导的"。
5. **闭环四环节缺一不可**——报告（失效信息入库）→ 分析（机理与原因）→ 纠正（措施落到设计/工艺/筛选/使用/管理）→ 验证（实际应用中确认措施有效、同类失效不再现）。缺验证环节的"闭环"会退化为一次性报告。

## A1 · 案例

**案例 1（继电器弹簧片断裂，R-1/R-2 源书）**：春存秋用的大批继电器弹簧片沿晶界断裂。单看器件：材料与工艺无异常。扩大到环境：仓库南门外田野有鸡粪堆，氨气经夏季南风入库，提供应力腐蚀必需介质 → 判定为氨致应力腐蚀开裂。教训：**不扩大系统边界，结论永远到不了根因**。

**案例 2（轴件疲劳寿命偏低，R 源书统计归因示例）**：断口确认为疲劳、源于齿根。候选原因三四个（齿根圆角半径/脱碳层/硬度/夹杂物），用多重秩和显著性检验排序——前三个因素 H 值均低于临界值（可信度不足 80%），唯独塑性夹杂物显著 → 根因收敛到材料夹杂。教训：**候选原因间的取舍要靠量化检验，不靠直觉**。

## A2 · 触发场景

- "失效分析报告写完了，但产线问题还是反复出现" → 查闭环四环节缺哪环（多半缺验证）；
- "客户投诉批次性失效，怎么组织排查" → 五要素清单 + 批次聚集性判断 + 四M 撒网；
- "失效原因候选有好几个，哪个才是主导" → 显著性检验思路（多重秩/H 检验），先量化排序再收敛；
- "怎么给客户端建可追溯的失效管理体系（FRACAS）" → 报告-分析-纠正-验证四环节落库设计，配合 SN/批次追溯字段；
- "失效分析结论怎么防止误判" → 结果验证（实际应用再现性）+ 好品对照模拟试验。

## E · 执行步骤

1. **收信息**：按五要素清单（批次认可/时空/产品记录/工作条件/失效详情）逐项核对，缺项向委托方追要；记录失效比例与批次分布。
2. **定边界**：把失效对象放进"设备—环境—人"三元系统，画出至少三层的环境/使用/管理边界，每层写一句"该层是否存在嫌疑"。
3. **撒网**：按四M 列全候选因素（人：资质/操作；机：设备/工装；介质：温度湿度污染气氛；管理：程序/维护/筛选制度）。
4. **收口**：能做对照试验的做对照；多因素候选时用显著性排序（多重秩检验思路或等效统计方法）挑出主导因素；无法量化时列出各因素的支持/反对证据再裁决。
5. **落纠正**：措施按「设计/工艺/材料/筛选/使用条件/质量管理」六类归类，每条注明责任方与生效节点。
6. **闭环验证**：设定验证判据（同类失效再现率、参数稳定性窗口），在真实应用中跟踪；验证通过才允许关闭案例，未通过回到第 3 步。
7. **归档反哺**：案例入库（模式/机理/原因/措施/验证结论五字段），反馈给设计与工艺做举一反三。

## B · 边界

- 本技能是**管理体系与归因方法论**，不替代任何具体分析技术；技术选型见 `./chip-fa-characterization`、`./chip-fa-localization`。
- 四M/整体观念源书为**机械构件失效分析**教材，迁移到电子器件场景时"介质"应扩展为温湿度/污染/偏压气氛等电子应力，**不可机械照搬金属断口判据**。
- 多重秩检验的临界值表属统计学工具，本书只给出方法思路与示例，具体临界值须查统计学手册，不得引用本书示例数值作判据。
- FRACAS 的字段与流程落地须结合企业质量体系（如 IATF 16949 / 8D / 质量归零），本技能只提供方法论骨架。
- 源书成书年代较早（1980s–2000s），涉及具体管理表单格式以企业现行体系为准。
