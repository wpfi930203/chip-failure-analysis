## R · 原文锚点

> 层次的约定和单元划分是开展 FMEA 的关键环节。首先根据元器件的结构进行层次约定，初始约定层次即为元器件本身，然后根据元器件的复杂程度向下分解为第二、第三等层次，最低约定层次应为潜在失效机理发生的层次。
>
> ——第 17 章 17.2.5

> 在构建元器件故障树时，失效物理的本质内容（失效模式、失效部位、失效机理、机理因子、影响因素）决定了元器件故障树各事件之间的相互关系。
>
> ——第 18 章 18.3.2

> 建树时不允许逻辑门—逻辑门直接相连。若建树时出现逻辑门—逻辑门相连而又根本不能严格定义，很容易发生逻辑关系错误，无法进行 FTA 分析。
>
> ——第 18 章 18.2.3

> 在正常情况下，一批产品的统计量相应的点以很大的概率落在上、下控制线之间，即认为产品生产过程是处于稳定状态，如果落在上、下控制线之外（或相继的点呈现异常的趋势），就认为出现了不稳定因素。
>
> ——卢其庆 1980 §10.5

## I · 骨架：预防的三条腿

```
失效预防
├─ FMEA（自下而上、归纳）→ 找潜在失效模式/机理，算风险等级，定措施
├─ FTA （自上而下、演绎）→ 从顶事件反推原因组合（与门/或门），求最小割集
├─ SPC  （过程横向监控）→ 控制图发现过程异常趋势，把波动拦在批次失效之前
└─ 工程防护（把机理消灭在条件层面）→ 潮敏/机械/腐蚀/ESD/闩锁/假冒/其他
```

**四者的分工**：FMEA/FTA 是**设计侧**的失效预防（找什么会坏、为什么坏）；SPC 是**过程侧**的失效预防（监控工艺参数波动，防止工艺漂移制造出缺陷品）；工程防护是**条件侧**的失效防护（潮敏/ESD 等环境与操作条件管控）。

**FMEA 与 FTA 的分工**（书内第 18 章）：

| | FMEA | FTA |
|---|---|---|
| 方向 | **自下而上**（归纳） | **自上而下**（演绎） |
| 起点 | 单元（功能单元） | 顶事件（不希望发生的故障） |
| 回答 | "这个单元可能怎么坏、坏了会怎样" | "这个失效要发生，需哪些原因同时/任一成立" |
| 产出 | 失效机理的 FMEA 列表 + 风险等级 | 最小割集族 + 失效路径 |

**FTA 的两种建树路径**：模块级产品用「**基于功能逻辑关系**」建树，底事件落在元器件产品层面；元器件用「**基于失效物理**」建树，底事件落在元器件**内部物理结构层面**。两者互补衔接——这正是本书的独立贡献，元器件 FTA **不能照搬**系统 FTA 的功能逻辑。

## A1 · 案例：元器件级 FMEA 的功能单元划分与编码

书内以混合集成电路为例（表 17-2），把产品划为**两个层次**：第一层次为有源芯片、无源元件、基板、腔体、外引线；第二层次为封装后的整体产品。

| 层次 / 类别 | 单元名称与代码 |
|---|---|
| 有源芯片 | 电路芯片：混合集成电路-02-F01；分立芯片：混合集成电路-02-F02 |
| 基板 | 混合集成电路-02-F03 |
| 腔体 | 混合集成电路-02-F04 |
| 外引线 | 混合集成电路-02-F05 |
| 无源元件 | 电阻 -02-F06；电容 -02-F07；电感 -02-F08；变压器 -02-F09 |
| 键合 | 混合集成电路-02-J01 ~ 02-J06 |
| 黏结 | 混合集成电路-02-J07 ~ 02-J10 |

**三条可直接复用的规则**：

1. **没有信息就不分析**："分析从有足够信息的且感兴趣的最低级别开始"。**信息不足的层次可以不下钻**，这是防止 FMEA 变成填表游戏的关键。
2. **最低级别的选择由"你关心什么"决定**：只对**封装工艺缺陷**感兴趣 → 最低级别按封装结构划分为芯片、基板、外引脚；对**芯片内部工艺**感兴趣 → 可再往下拆为金属化、多晶硅、硅衬底。
3. **每个功能单元必须有唯一编码**：目的是"对元器件的每个失效机理/模式进行统计、分析、跟踪和反馈"。

## A2 · 案例：厚膜 HIC「无输出」质量归零（FTA 全流程，书内 18.4.3）

这是本书唯一完整的 FTA 归零案例，**失效路径链条完整、可以照搬这个推理格式**。

**背景**：金属气密封装厚膜 HIC，存放数年后使用出现"无输出"。

**① 失效路径（从现象到机理，逐层收敛）**

```
故障 HIC（顶事件：故障对象）
  → 无输出（二层：失效模式）
    → N2 芯片无输出（三层：失效部位，由功能逻辑分析定位）
      → N2 芯片键合开路（四层：失效机理）
        → Au 丝键合点 Al 腐蚀开路（机理细化）
```

**② 关键推理**：开帽检查发现 N2 芯片多个**Au-Al 丝键合部位腐蚀**；由于 N2 芯片—键合丝开路导致 A 点开路，使 A 点始终处于 +30V 高电平，截止 M1，故输出为 0V。**注意这里用的是排除性推理 + 电路逻辑验证，不是"看到腐蚀就归因"**。

**③ 机理确认**：微区成分分析确认 Au 丝与芯片盘之间的 Au-Al 键合部位，裸露 Al 在**水汽（H₂O）与污染离子（Cl⁻、K⁺、Na⁺）**作用下逐渐腐蚀，产生絮状 Al(OH)₃，最终开路。

**④ 提取机理子树（以影响因素为底事件）**：失效机理事件下挂三层——**机理因子**（沾污、水汽、温度）→ **影响因素**（组装中原芯片内部沾污转移、水汽释放、气密泄漏、水汽超标、低于露点温度等）。

**⑤ 归零措施（由机理因子反推控制方向）**：沾污、水汽、温度三点是控制键合点腐蚀的关键，应结合生产能力与技术能力**从三者中选择重点控制方向**；对未能满足水汽门限的产品，重点控制**使用温度，原则是避免在 0℃ 以上出现露点**；加强气密封装工艺的水汽控制与组装过程沾污离子控制。

> **这个案例的可复用价值**：它示范了「**FTA 不是画图，而是把归零措施反推到可执行的控制参数**」——措施直接落在机理因子（水汽/沾污/温度）而不是笼统的"加强管控"。

## A3 · 案例：潮敏失效的完整链条与标准体系

**潮敏失效的五种表现（书内 19.1.1）**：

1. 受潮的塑封器件在**没有高温作用**的情况下，内部结构黏结性不好 → 出现分层 → 表现为开路、短路、漏电；**若有腐蚀性杂质离子存在，可导致金属化腐蚀**。
2. 受潮的塑封器件在**高温作用**下膨胀变形，由于热失配导致内部结构出现分层 → 开路、短路、漏电；严重者器件背面产生鼓包，即"**爆米花**"效应。
3. 受潮后塑封器件若膨胀变形严重，**形变应力会导致芯片破裂** → 开路、短路、漏电。
4. **由于水是有极性的**，塑封器件吸收了大量潮气后，**不管是否发生了变形或分层，都会有漏电现象**。
5. 塑封器件受潮后，**有可能在遇到热应力的瞬间就立即失效，也有可能在长期的正常使用过程中才逐渐失效**（潜伏期）。

**第 4 条与第 5 条是这个案例最有价值的部分**：它们解释了为什么"潮敏"难以被常规出厂筛选拦住——**漏电可以无变形发生**，**失效可以在很久以后才发生**。

**标准体系（书内给出）**：IPC-M-109《潮湿敏感器件标准与指导》共七个文件，其中三个直接相关——
- **IPC/JEDEC J-STD-020**：塑封集成电路（IC）SMD 的潮湿/回流敏感性分类（**MSD 分 6 大类**）
- **IPC/JEDEC J-STD-033**：潮湿/回流敏感性 SMD 的处理、包装、装运和使用标准
- **IPC-9503**：非 IC 元件的潮湿敏感性分类

**检测手段**：常用 X-ray（或 3D X-ray）检测、扫描声学显微镜检测。**扫描声学显微镜用无损方式探测裂纹、空洞和分层。**

## A4 · 案例：微波功率管引线键合系统的 FMEA（书内 17.3.2，三张列表）

书内以微波功率管为例给出**同一"引线键合"单元的三种不同失效机理**各自独立的 FMEA 列表——**一个单元 ≠ 一个失效机理**，这是最容易做错的地方。

| 潜在失效机理 | 潜在失效模式 | 失效影响 | 潜在失效原因 | 加速因子 | 控制与纠正措施 |
|---|---|---|---|---|---|
| **键合工艺差错** | 接触不良或引线脱落 | 半导体器件失效的 **1/3~1/4** 由引线键合引起，易造成短路失效 | ① 键合点宽度过宽（横截面缩小、压点间距过小易短路）② 键合丝碎屑位移（超声功率/压力/劈刀形状造成毛刺飞溅，导致相邻金属条短路）③ 压键处过长尾丝（质心远离固定位置，外力下断裂成可动导电多余物，造成**瞬间短路**） | 振动应力 | **封盖前内目检**，剔除或修复有键合缺陷的产品 |
| **内引线断裂和脱键** | 接触不良或引线脱落 | 同上 | 分三类：① 键合丝损伤→**中间断裂**（面积减小→电流密度加大→过流烧毁；抗机械能力下降；源于机械损伤与化学腐蚀）② **键合点根部断裂**（键合工艺引入）③ **键合点脱键**（高频致命失效，多在引出端焊盘；源于焊盘镀层缺陷如过薄/材料不纯致镀层太硬/颗粒过细致表面太光滑，以及有机沾污） | 机械应力、温度、化学腐蚀 | 控制键合工艺、优化焊盘镀层、避免沾污、封盖前加强目检 |
| **热循环使引线疲劳** | 接触不良或引线脱落 | 同上 | 硅铝合金丝受导热循环和高低温冲击，热胀冷缩，经多次反复致使**金属疲劳** | 温度循环幅值（Coffin-Manson 模型，C 与 m 为与金属材料特性有关的常数） | ① 控制键合工艺避免应力损伤 ② 避免涂胶工艺 ③ 评估键合点的疲劳寿命 |

> **脱键的特殊危害（值得单独记住）**：脱键是**逐步退化**的过程，在目检和考核时可以达到要求，但随时间推移键合强度逐渐下降，高温下快速退化直至脱键。**即"出厂合格"不能证明脱键风险已消除。**

## E · 执行步骤

### 一、元器件级 FMEA

**准备工作：必须获得并熟悉四类信息（书内 17.2.5）**

| 信息类别 | 内容 |
|---|---|
| **功能信息** | 元器件具有的功能与所起的作用，包括设计、结构、性能指标（如电功率、器件温升和热点等） |
| **工艺和结构信息** | 外形、封装和接口形式；采用的生产工艺（薄膜/厚膜电路、单片集成、微组装等）；材料；组成单元及其特征、性能、作用和功能；**通过各单元之间的逻辑关系获得结构框图** |
| **使用和环境信息** | 在电路图上的位置、作用，工作条件和偏置状况 |
| **可靠性信息** | 该元器件或同类元器件在设计、生产、试验及使用过程中的**失效信息、失效率及寿命数据**，也可从文献资料及标准中获得 |

**十步分析程序（书内 17.2.4）**

1. 准备工作，收集信息
2. 层次和功能单元划分
3. 功能单元编码
4. 确定潜在失效机理 / 模式
5. 潜在失效机理 / 模式影响分析
6. 分析每种失效机理 / 模式的**相关应力**；适用时还需**建立失效机理物理模型，确定各应力的加速系数**
7. 分析失效影响的**风险等级**，并根据元器件的寿命周期对各个失效阶段进行风险等级评估
8. 根据每种失效机理的相关应力、失效原因、失效影响及风险等级，提出**有针对性的预防和改进措施**
9. 汇总失效影响分析结果和引起失效机理的失效原因等资料，获得**元器件失效机理的 FMEA 列表**
10. **可能时，对失效影响分析结果进行验证**

**风险等级算法（书内 17.2.5 第 5 条）**

```
R = S × O
  R —— 失效影响的风险等级
  S —— 失效影响的严重度等级（4 级）
  O —— 失效发生频率的等级（5 级）
```

**严重度等级 S（4 级）**

| 等级 | 影响水平 | 对元器件产品的影响后果 |
|---|---|---|
| 1 | 轻微 | 功能略有降低或参数略有变化 |
| 2 | 中等 | 功能降低或参数有变化 |
| 3 | 较重 | 功能明显降低或参数显著变化 |
| 4 | 严重 | 功能突然失效、短路或开路 |

**发生频率等级 O（5 级）** —— 等级划分如下（失效率与等级的对应关系可依元器件情况自行确定）：

| 等级 | 发生频度 | 失效率量级 |
|---|---|---|
| 1 | 不大可能发生 | 10⁻¹⁰ 及以下 |
| 2 | 很少发生 | 10⁻⁷ ~ 10⁻⁸ |
| 3 | 偶尔发生 | 10⁻⁵ ~ 10⁻⁶ |
| 4 | 很有可能发生 | 10⁻³ ~ 10⁻⁴ |
| 5 | 经常发生 | 10⁻¹ ~ 10⁻² |

**风险等级 R 的合并简化**：S×O 共得 **20 个理论组合**；为便于工程应用，将 1~2 合并为 1、3~4 合并为 2，依此类推，并将严重影响的 12 定义为 7、16 定义为 9，最终得到 **1~10 级**的简化风险等级。

> ⚠️ **发生频率 O 的确定是全书最强调"困难"的一步**：需通过标准/文献/资料调研，收集生产方与用户方的试验与现场失效信息及大量案例并统计分析；**且必须考虑元器件寿命周期的不同阶段**——按**早期失效、随机失效、耗损失效**分别统计（例如影响寿命的机理在早期和随机失效阶段的发生频率会远小于进入耗损阶段）。

**失效原因的三期推断（书内 17.2.5 第 6 条）** —— 用"失效发生期"快速缩小原因范围：

| 失效期 | 主要失效原因 |
|---|---|
| **早期失效** | 工艺缺陷、原材料缺陷、筛选不充分 |
| **随机失效** | 整机开关时的浪涌电流、静电放电、过电损伤 |
| **磨损失效** | 电子元器件自然老化 |

> 书内原话的意思是：**根据失效发生期可估计失效原因，加快失效分析的进度**。
> 注意与 `chip-fa-stress-test` 的 B 段（早期/偶然/耗损的失效时间特征分类）配合使用。

**应力类型 → 失效模式/机理对照（书内表 17-3，FMEA 定"相关应力"时直接查）**

| 应力类型 | 试验方法 | 可能出现的主要失效模式或机理 |
|---|---|---|
| 电应力 | 静电、过电、噪声 | MOS 元器件的栅击穿、双极型元器件的 PN 结击穿、功率晶体管的二次击穿、CMOS 电路的闩锁效应 |
| 热应力 | 高温储存 | 金属—半导体接触的 Al-Si 互溶、欧姆接触退化、PN 结漏电、Au-Al 键合失效 |
| 低温应力 | 低温储存 | 芯片断裂 |
| 低温电应力 | 低温工作 | 热载流子效应 |
| 高低温应力 | 高低温循环 | 芯片断裂、芯片黏结失效 |
| 热电应力 | 高温工作 | 金属电迁移、欧姆接触退化 |
| 机械应力 | 振动、冲击、加速度 | 芯片断裂、引线断裂 |
| 辐射应力 | X 射线辐射、中子辐射 | 电参数变化、软错误、CMOS 电路的闩锁效应 |
| 气候应力 | 高湿、盐雾 | 外引线腐蚀、金属化腐蚀、电参数漂移 |

**分析计划的三项约定（书内 17.2.3）**

| 项 | 内容 |
|---|---|
| 分析类别 | ① 针对**各种典型元器件类型和工艺**开展，编制**通用 FMEA 信息列表**；② 针对**特定元器件类型或型号**开展，编制特定产品 FMEA 信息列表。**两种计划中都要确定表格格式、约定层次与编码体系** |
| 表格格式 | 每一张表格上应注明**初始约定层次（元器件名称）**；每一相继的约定层次的分析应记录在单独的分析表或一组分析表上 |
| 最低约定层次 | 一般为**元器件的最小单元**，是失效发生的最小部位，**必须具有独立的失效机理**；也可根据分析需要自行确定 |

**FMEA 列表的基本内容（表 17-8 的结构）**：代码 / 单元或连接方式名称 / 潜在失效机理 / 潜在失效模式 / 潜在失效原因 / 潜在失效影响 / 潜在失效机理的加速因子 / 预防和改进措施 / 风险等级（**按早期失效、随机失效、耗损失效分别给风险等级**）。

**FMEA 的双向收益（书内 17.2.2）**

- **对元器件生产厂**：帮助设计人员开展可靠性设计（选择结构/材料/工艺最佳方案）、帮助生产人员进行工艺控制和优化、提高元器件固有可靠性。
- **对元器件使用方**：① 帮助根据实际使用条件和要求**选择正确、合适的元器件**；② 帮助开展必要的**系统可靠性设计**，保证应用可靠性；③ 提高使用可靠性从而提高系统可靠性。

### 二、FTA · 六层故障树结构（书内 18.3.2，图 18-1 / 18-2）

**这是元器件 FTA 的核心骨架：按失效物理把顶事件向下拆成 6 层（n ≥ 6）。**

| 层 | 事件名称 | 含义 | 示例 |
|---|---|---|---|
| ① | **顶事件 = 故障对象** | 按元器件类别区分 | 继电器故障、晶体管故障、电容故障 |
| ② | **失效模式** | 元器件单独复测表现的失效现象 | 参数漂移、无输出、管腿断、烧毁开路、短路、封装失效 |
| ③ | **失效部位** | 对失效类别的进一步定位与现象描述 | 断腿/绝缘子开裂、内引线断/元件脱落、芯片参数漂移；模块/组件需结合功能逻辑分析确定 |
| ④ | **失效机理** | 失效的物理 / 化学过程 | 键合点腐蚀开路、Au-Al 界面退化、颈缩断裂、电迁移、TDDB |
| ⑤ | **机理因子** | 失效机理发生的**内在主导因子** | 芯片 Al 腐蚀的因子：水汽、沾污、温度 |
| ⑥ | **底事件 = 影响因素** | 形成机理因子的**外部原因或来源** | 芯片 Al 腐蚀的水汽因子来源：泄漏、释放、原有 |

**逐层关系**：故障对象 ← 失效模式 ← 失效部位 ← 失效机理 ← 机理因子 ← 影响因素。
即每一层事件由其**更低一层的直接原因事件**组成，这种直接原因事件是决定上层事件发生的**必要且充分**的原因。

**底事件的定位可以按目的调整**：针对**机理研究** → 底事件定位在失效机理或影响因素；针对**机理控制/故障改进** → 底事件定位在外部原因。

**失效路径的完整表述格式（案例 A2 已验证）**：

```
故障对象 → 失效模式 → 失效部位 → 失效机理 → 机理因子 → 影响因素
```

### 三、FTA · 五条建树规则（书内 18.2.3，模块级；元器件同理）

1. **确定分析目的与顶事件定义**，并画出产品的功能逻辑关系图作为建树依据。需透彻了解对象产品的故障逻辑关系，找出导致顶事件的所有基本故障原因事件或组合。
2. **推荐采用人工演绎法建树**。演绎时首先寻找的是**直接原因事件**而非基本原因事件（底事件），应不断用"直接原因事件"作为过渡，**逐步地、无遗漏地**将顶事件演绎为基本原因事件；过程中常用等价的、更具体的或更直接的事件取代较抽象的事件。
3. **应从上向下逐级建树**。目的是**避免遗漏**：先定顶事件，再定下一层所有直接事件，分层次建造，**从上到下进行演绎的逻辑要相同，避免中途改变逻辑关系**。
4. **不允许逻辑门—逻辑门直接相连**。若出现逻辑门—逻辑门相连而又根本不能严格定义，很容易发生逻辑关系错误，**无法进行 FTA 分析**。
5. **妥善处理共因事件**。来自同一故障源的共同故障原因会引起不同部位发生故障。共因事件对系统故障概率影响很大，必须妥善处理。
   - 书内例子：HIC 内部多个部位同时发生水汽腐蚀失效，虽然**腐蚀机理相同但部位不同**，最终导致的 HIC 失效模式可能不同 —— 此时的水汽腐蚀机理事件称为**共因事件**。

**⑥ 建树后的强制动作**：建成的故障树应请**既有实际产品经验又懂得可靠性知识的、未参加建树的人员**审查；经审查并改正后的故障树才能成为分析的基础，**此时建树工作才算完成**。

> **可复用的工程建议（书内原意）**：对电子元器件而言，同类元件/器件产品的结构材料具有很大相似性，故障问题也基本相同，故可以**针对一类元件或器件建立一个基本结构的完整故障树，形成「故障树基础库」并持续扩展更新**，支撑今后的 FTA 工作。

### 四、FTA · 简化与模块分解（书内 18.3.3 / 18.2.4）

**目的**：减少分析工作量。**注意：简化和模块分解并不是 FTA 的必要步骤**，是"有效措施"而非必经环节。

**元器件 FTA 的四类共因失效机理子树集**（机理子树由故障树的**第四、五、六层**事件构成）：

| 子树集 | 名称 | 内容 |
|---|---|---|
| **A** | 退化性失效机理子树集 | A = {A₁, A₂, …, Aᵢ, …, Aₙ} |
| **B** | 瞬时性失效机理子树集 | B = {B₁, B₂, …, Bᵢ, …, Bₙ} |
| **C** | 缺陷性失效机理子树集 | C = {C₁, C₂, …, Cᵢ, …, Cₙ} |
| **D** | 使用不当失效机理子树集 | D = {D₁, D₂, …, Dᵢ, …, Dₙ} |

**组件产品的故障模块子树集 E**：对 HIC 等组件，把**各类分立元器件故障树视为故障模块子树**，E = {E₁, E₂, …, Eᵢ, …, Eₙ}；按需选择元器件完整子树或某种失效模式的部分子树，通过**故障模块子树导入**简化 HIC 或组件故障树。

**虚设底事件故障树（快速降维技巧）**：把 6 层故障树简化为 **3 层、4 层或 5 层** —— 分别以"失效模式事件"、"失效机理事件"、"机理因子事件"为底事件，把各事件子树等效为一个**模块子树**，每个模块子树用一个**等效的虚设底事件**代替，使原故障树规模减小、更清晰。

**简化的两个操作手法**：采用**相同转移符号**表示相同子树，**相似转移符号**表示相似子树（例：同一器件不同部位的腐蚀机理相同，可用相同转移符号表示相同的机理子树）。

### 五、FTA · 定性分析：求最小割集（书内 18.3.4 / 18.2.5）

**分析目的**：找出导致元器件发生故障的**失效部位、失效机理、机理因子和影响因素**，以及识别导致失效模式事件发生的**所有失效机理最小割集**、诱发失效机理的**所有机理因子最小割集** —— 即元器件的**薄弱环节**。

**四个步骤**

1. 确定分析的故障树：提取**特征故障子树**或**虚设底事件故障树**
2. 求出**全部最小割集**
3. 所有最小割集按重要性排序
4. 所有底事件按重要性排序

**两种求法**

| 方法 | 方向 | 规则 | 产出 |
|---|---|---|---|
| **上行法** | 从**底事件**开始，自下而上做事件集合运算 | 或门输出 = 输入事件的**并**（布尔和）；与门输出 = 输入事件的**交**（布尔积）。层层代入，过程中或最后按布尔代数**吸收律和等幂律**化简，将顶事件表示成底事件**积之和的最简式** | 每一积项对应一个最小割集，全部积项即是所有最小割集 |
| **下行法** | 从**顶事件**开始，逐级向下寻查 | 顺次将逻辑门输出事件置换为输入事件：遇**与门**→输入事件排在同一行（取**交**）；遇**或门**→输入事件各自排成一行（取**并**）；直到全部置换成底事件。得到割集后**两两相比，划去非最小的割集** | 剩下即为全部最小割集 |

**最小割集表示顶事件**：T = ∪ ( ∩ Xᵢ )，其中 ∪ 为并集、∩ 为交集、Xᵢ 为第 i 个底事件。

**两条重要性判据（直接可用）**

| 对象 | 判据 |
|---|---|
| **最小割集重要性** | 在各个底事件发生概率比较小且差别相对不大的条件下，**阶数越小的最小割集越重要** |
| **底事件重要性** | ① 在**低阶**最小割集中出现的底事件比高阶最小割集中的底事件重要；② 同一最小割集阶数条件下，在**不同最小割集中重复出现次数越多**的底事件越重要 |

**特征故障子树的用法**：以"失效机理事件"为顶事件、以"机理因子事件"为底事件做机理子树最小割集分析，可获得**引起失效机理发生的机理因子原因及其原因组合**。

**现实约束（书内明确）**：由于元器件失效物理的特性，对其**完整故障树进行全面定性分析是不现实也没有必要的**，可以提取需要分析的**故障子树**进行分析。

### 六、FTA 的两个应用方向（书内 18.4）

**① 针对质量问题归零**（对应"双五归零"：定位准确、机理清楚、问题复现、措施有效、举一反三）

| 步 | 动作 |
|---|---|
| 1 | **故障树建造**：确定归零分析目标（顶事件），建造基于失效物理的元器件故障树 |
| 2 | **故障树节点事件测试验证**：检测元器件热、电、机械、气密等电性能和物理特性，**对照故障字典**，根据测试获得的**失效特征向量**分析确定机理原因 |
| 3 | **定性定量分析**：根据机理子树分析所有可能的机理因子和影响因素及其组合；用最小割集法对影响因素重要性排序 |
| 4 | **故障路径分析**：按失效模式 → 失效部位 → 失效机理 → 机理因子 → 影响因素的结果与逻辑关系，确定故障路径与最终影响因素 |
| 5 | **失效模式、机理和影响因素确认**：根据故障路径结果确认 |
| 6 | **归零要素分析建议**：提出故障复现试验方案设计建议、失效控制策略及措施建议、举一反三关键点检查建议 |
| 7 | **编写元器件 FTA 报告** |

**② 针对可靠性设计** —— 与 FMEA **联合使用**：

1. 对元器件/微组装组件做 **FMEA**，通过列表分析与危害度定量分析，对使用环境下每个单一潜在失效模式的影响及危害性排序，**确定主要潜在失效模式**（作为可靠性设计首要控制对象）。
2. 针对主要潜在失效模式做 **FTA**：建立失效物理故障树，通过该模式下的**机理子树 FTA**，对机理因子底事件和影响因素底事件的最小割集分析，**确定必须控制的主要失效机理**，并找出消除诱发失效机理的关键影响因子与最佳控制对策。

**FTA 与 FMEA 联合使用的四个优点（书内 18.4.2）**

1. FTA 是**自上而下**、FMEA 是**自下而上**，**演绎与归纳联合**可确保潜在失效模式和失效机理分析的**完整性**。
2. 安全标准中常需要**单一故障分析**，而这些分析正是通过完成 FTA 获得的。
3. 对**全面确认底事件及其危害性**，FMEA 是有用方法；对**不希望出现的顶事件的原因分析**，FTA 是实用方法。
4. 可做**一致性检查**：FMEA 中确认的任何导致顶事件发生的单一失效**也必须为单点故障**（在最小割集中）；FTA 已确认的单点故障**也应当在 FMEA 中出现**。**两者各自独立进行时，这种一致性检查的价值更高** —— 这在安全性分析中尤为重要。

### 八、SPC · 质量控制图（卢其庆 1980 §10.5，v2.0.0 新增）

**控制图是什么**：在生产的某一环节对某批产品随机抽样测量，算出规定统计量（平均值、极差等），以批次/时间为横坐标、统计量为纵坐标描点，作出**中心线 CL** 与**上下控制线 UCL/LCL**。

**3σ 管理法原理**：控制界线的确定办法有两种——a. 正态分布标准偏差的 **±3 倍**；b. 按标准值和公差要求确定。对正态统计量，落在 x̄±3σ 区间内的概率为 **99.7%**（一千个产品只有约 3 个在范围之外）——落在外面是小概率事件，发生了就认为**过程出现异常**。这就是 3σ 管理图法的根基。

**建图的标准动作（书内明确）**：真实的 x̄ 和 R̄ 是不知道的——对**比较稳定的生产过程，一般取 20～25 批数据（每批抽 n 个）**，把各批的均值与极差的均值当作真值，先验证这批点全部落在控制线间且无异常趋势，**才能作为后续生产控制的基准**。

#### 1. 均值—极差控制图（x̄-R 控制图）

每批抽 n 个测特性值 x，算每批均值 x̄ 与极差 R = max(xᵢ) − min(xᵢ)（注意 R 与可靠性函数 R(t) 无关）。x̄ 的控制限用 A₂·R̄ 代替 3σ（σ 估计 = R̄/d₂，d₂ 为与 n 有关的常数）：

```
均值图：UCL = x̄̄ + A₂·R̄     CL = x̄̄     LCL = x̄̄ − A₂·R̄
极差图：UCL = D₄·R̄          CL = R̄      LCL = D₃·R̄
```

（D₄ = 1 + 3d₃/d₂，D₃ = 1 − 3d₃/d₂；x̄ 图与 R 图**必须两者同时运用**，任一张越界都要检查过程。）

**x̄-R 控制系数表（书内表 10.8 节选）**：

| n | A₂ | D₃ | D₄ |
|---|---|---|---|
| 2 | 1.880 | 0 | 3.267 |
| 3 | 1.032 | 0 | 2.575 |
| 4 | 0.729 | 0 | 2.282 |
| 5 | 0.577 | 0 | 2.115 |
| 6 | 0.483 | 0 | 2.004 |
| 7 | 0.419 | 0.076 | 1.924 |
| 8 | 0.373 | 0.136 | 1.864 |
| 9 | 0.337 | 0.184 | 1.816 |
| 10 | 0.308 | 0.223 | 1.777 |

**原著算例（氧化层厚度监控）**：氧化工艺每批抽 4 只测厚度，10 批数据得 x̄̄ = 1439 埃、R̄ = 206 埃。查表 n=4：A₂=0.729、D₄=2.28、D₃=0。
- 均值图：UCL = 1439 + 0.729×206 = **1591.3 埃**，LCL = **1286.3 埃**
- 极差图：UCL = 2.28×206 = **470 埃**，LCL = 0
- 结论：各批点全部在界内、无异常趋势 → **过程稳定**。

#### 2. 不合格品率控制图（p 图）与不合格品数控制图（pn 图）

不合格品率服从二项分布，但 n 较大时按中心极限定理近似正态，标准差 = √(p̄(1−p̄)/n)：

```
p 图： UCL = p̄ + 3·√(p̄(1−p̄)/n)    CL = p̄    LCL = p̄ − 3·√(p̄(1−p̄)/n)
pn 图：UCL = p̄n + 3·√(p̄n(1−p̄))    CL = p̄n   LCL = p̄n − 3·√(p̄n(1−p̄))   （n 大时用 pn 代替 p）
```

p̄ 未知时同样**取 20～25 批**，用总不合格品数 ÷ 总样品数作实际不合格率。

**原著算例（封焊不合格率）**：连续 25 批、每批 100 支器件，不合格总数 283 → p̄ = 11.5%。
- UCL = 0.115 + 3×√(0.115×0.885/100) = **0.210**，LCL = **0.020**

**适用场景**：产品需综合考虑多种特性值或特性不易量化（如**管壳**外观类质量）时，p 图是综合质量指标的好选择；主要用于**全数检查**的结果（数量多时才反映真实动态）。

#### 3. 缺陷数控制图（c 图 / 疵点图）

缺陷数 c 服从泊松分布，标准差 = √c̄；c 较大时近似正态：

```
c 图：UCL = c̄ + 3·√c̄    CL = c̄    LCL = c̄ − 3·√c̄
```

#### 4. 控制图的三大用途（书内归纳，工程上最有操作价值）

| 用途 | 说明 | 半导体场景实例 |
|---|---|---|
| **判别工艺/质量稳定性** | 稳定 ≠ 特性值完全相同，而是波动在控制限内 | 判断氧化/扩散参数是否受控 |
| **查究不稳定根源** | 越界点指向原料、设备、技术熟练度、工艺条件等 | p 图**低于 LCL** 的点可能是先进工艺/方法造成——**好异常也要查原因并固化** |
| **觉察质量的缓慢变化** | 点子呈缓慢定向漂移时，人未觉察图已显示 | 去离子水、光刻胶质量下降等慢性劣化，可及时发现纠正 |

此外控制图还可用于作出技术决定、产品质量评比与技术资料档案。

> **与 FMEA 的衔接**：FMEA 表 17-8 中「按早期/随机/耗损失效分别给风险等级」所依赖的过程数据，其**受控状态**正是由这些控制图保障的——过程失控时统计的 O 等级（发生频率）会系统性失真。SPC 越界本身就是 FMEA 输入数据可信度的前提。

## B · 边界（**重要，涉及与现行 FMEA 体系的关系**）

1. **本书的 FMEA 是"元器件级 FMEA"，成书于 2015 年，方法论载体较早。** 它以 **R = S × O** 的风险等级与"约定层次 + 编码体系"为核心。如果你的组织已采用 **AIAG & VDA FMEA 2019 七步法**（结构分析 → 功能分析 → 失效分析 → 风险分析 → 优化 → 结果文件化），**两套体系不能直接混用表格**：
   - 本书的"十步程序"与 2019 版的"七步法"**不是同一套步骤编号**，不能互相引用；
   - **本书用的是 R = S × O（严重度 × 发生频率），既不含"探测度 D"，也没有 2019 版的 AP（Action Priority：H/M/L）**。旧版三因素 RPN（S×O×D）同样**不是**本书的算法。**不可把 R=S×O 的阈值当 2019 版 AP 判据，反之亦然**；
   - 本书**未涵盖 2019 版的"结构树 / 功能网 / 失效网"三层建模**，也无"失效影响/失效模式/失效原因"的 7 类失效链（FC/FM/FE）表述。
   **正确做法**：把本书当作**元器件级失效模式/机理的技术知识源**，把 AIAG & VDA 2019 当作**方法论框架与表格规范**，用本书填内容、用 2019 版管形式。
2. **FTA 的六层结构与五条建树规则是本书的独立贡献**，与 FMEA 版本无冲突，可直接使用。但注意：本书 FTA 的**定量分析只对混合集成电路、微波组件、微电路模块等模块级器件**进行——**分立元器件一般只做定性分析**（书内明确"对其完整故障树进行全面定性分析是不现实也没有必要的"）。
3. **第 19 章的工程防护引用了 IPC/JEDEC 标准号**，这些标准**持续改版**（MSD 等级划分、车间寿命、烘烤条件均可能已变）。**必须以现行版本为准**，书内只提供"哪些标准管这件事"的索引价值。
4. **本技能不提供任何具体防护参数**（温湿度阈值、车间寿命时长、水汽 ppm 门限、ESD 防护等级电阻值等）。书中案例出现的具体数值（如 GJB548 水汽 5000ppm）仅为该案例背景，**必须换成你产品的现行规范值**。
5. **失效预防的前提是失效分析已完成**。把 FMEA/FTA 当独立文档作业，会退化为"填表"，识别不出真实高风险项（见 A2 的失效模式确定依据）。
6. **止于"措施建议"**：本技能给出的是防护方向与判据，不替代可靠性设计评审，也不承担具体设计参数的确认责任。
